## 2. 基本設計の目的

本書は、AI会議秘書の要件定義を、実際に構築できるシステム構成へ落とし込むことを目的とする。

基本設計では、主に次の内容を定義する。

- プロトタイプの全体構成
- 利用者とシステムの関係
- Web画面の構成
- 画面間の遷移
- 会議データの処理フロー
- AI処理の構成
- Notionデータベースの構成
- n8nワークフローの構成
- 人による確認・承認の流れ
- 処理状況の見える化
- エラー発生時の処理
- 外部サービスとの連携方針
- Ver.0.1で実装する範囲

本書では、プログラム内部の細かな処理やAPIの項目までは確定しない。

API仕様、プロンプト、Notionの詳細項目、n8nノード構成などは、詳細設計で定義する。

## 3. プロトタイプの基本方針

AI会議秘書 Ver.0.1では、機能の多さよりも、次の一連の処理が安定して動くことを優先する。

```text
会議情報を入力する
    ↓
会議メモまたは文字起こしを登録する
    ↓
AIが会議内容を整理する
    ↓
議事録案を作成する
    ↓
決定事項とタスクを抽出する
    ↓
人が内容を確認・修正する
    ↓
人が承認する
    ↓
Notionへ登録する
    ↓
処理完了を表示する

Ver.0.1では、次の原則を守る。

1.生の会議データを上書きしない
2.AI生成結果と人の修正版を分けて保存する
3.AIが不明確な情報を勝手に確定しない
4.外部送信や正式確定には人の承認を必要とする
5.処理状況とエラー内容を利用者が確認できるようにする
6.AI、n8n、Notionをそれぞれ交換・修正しやすい構成にする
7.初期段階では手動入力を許容し、段階的に自動化する


## 4. システム全体構成

### 4.1 全体構成

AI会議秘書 Ver.0.1は、次の構成とする。

```text
┌─────────────────────────────┐
│           利用者             │
│ 経営者・会議主催者・参加者   │
└──────────────┬──────────────┘
               ↓
┌─────────────────────────────┐
│          Web画面             │
│ 会議入力・結果確認・修正・承認 │
└──────────────┬──────────────┘
               ↓
┌─────────────────────────────┐
│       バックエンドAPI         │
│ 入力受付・処理制御・履歴管理   │
└───────┬───────────┬─────────┘
        ↓           ↓
┌──────────────┐  ┌──────────────┐
│   AI処理層    │  │ 一時保存領域  │
│ 要約・分類    │  │ 生データ      │
│ 議事録生成    │  │ AI生成結果    │
│ タスク抽出    │  │ 処理状態      │
└───────┬──────┘  └──────────────┘
        ↓
┌─────────────────────────────┐
│        人による確認画面       │
│ 修正・承認・差し戻し・再生成   │
└──────────────┬──────────────┘
               ↓
┌─────────────────────────────┐
│       n8nワークフロー         │
│ Notion登録・通知・エラー処理   │
└──────────────┬──────────────┘
               ↓
┌─────────────────────────────┐
│       Notionデータベース      │
│ 会議・議事録・タスク・履歴     │
└─────────────────────────────┘

### 4.2 各構成要素の役割
構成要素	主な役割
Web画面	会議情報の入力、処理開始、結果確認、修正、承認
バックエンドAPI	入力受付、処理順序の制御、データ変換、状態管理
AI処理層	会議要約、発言分類、決定事項・タスク抽出、議事録生成
一時保存領域	生データ、AI生成結果、処理途中のデータを保持
確認・承認機能	人による修正、承認、差し戻し、再生成
n8n	Notion登録、通知、外部システム連携、エラー処理
Notion	承認済みの会議、議事録、タスク、処理履歴を保存
GitHub	設計書、ソースコード、プロンプト、n8n定義を管理

### 4.3 構成上の原則

システム全体は、次の原則に基づいて構成する。

Web画面からAIサービスやNotionを直接操作しない
バックエンドを通じて処理を制御する
生データはAI処理前に保存する
AI生成結果は生データとは別に保存する
人の承認前に正式データとして登録しない
Notion登録はn8nを経由する
外部連携に失敗しても、生データと承認済み結果を失わない
AIモデルを変更しても、Web画面とNotionへの影響を小さくする
各処理の開始、完了、失敗を履歴として記録する
処理途中でも、現在の状態を利用者が確認できるようにする

### 4.4 Ver.0.1の最小構成

初期プロトタイプでは、次の最小構成を実装する。

Web画面
  ↓
バックエンド
  ↓
AIによる議事録生成
  ↓
人による確認・承認
  ↓
n8n
  ↓
Notion登録

Ver.0.1では、次の機能を必須とする。
会議情報と会議メモの入力
AI処理の開始
処理状況の表示
議事録案の表示
決定事項の表示
タスクの表示
内容の修正
承認・差し戻し
Notionへの登録
処理履歴の保存
エラー内容の表示
再実行
